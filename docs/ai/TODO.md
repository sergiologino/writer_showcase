## В работу следующим (по приоритету)

1. **Локальный первоисточник материала и синхронизация (приоритет №1; ADR-012).** Реализованы IndexedDB и папка `publisher/<localId>/` с `content.md`, `media/`, `parameters.json`, локальное сохранение до API и просмотр папки из профиля. Медиа, выбранные в редакторе, пишутся в папку до загрузки на сервер; серверные вложения копируются при сохранении поста. Продолжение:
   - Этап 1 (осталось): поддержать чтение/запись в папку для браузеров без File System Access API или предоставить отдельный клиент; проверить сохранность и полноту больших медиа. Текущий вариант работает в браузерах с поддержкой выбора папки.
   - Этап 2: синхронизация с backend и другими устройствами: клиентский идентификатор уже есть локально; нужны серверная привязка, очередь изменений, повторная отправка без дублей, версии и сохранение обеих копий при конфликте. Синдикация в каналы — после явной публикации и успешной синхронизации материала.
   - Этап 3 (отложено по решению пользователя): массовый перенос существующих серверных постов и медиа в локальную папку, повторное подключение папки после удаления/переустановки или удаления аккаунта и восстановление локальной базы из файлов новой структуры.
   - Критерии приёмки: пост читается из папки без приложения; офлайн-правки не теряются; после возвращения сети и на втором устройстве появляется та же версия; конфликт не затирает текст; удаление приложения не удаляет папку. Для каждого этапа — автотесты и `npm run build`.

2. **Интеграция с нейросетями (углубление)**
   - Уже есть: noteapp-ai-integration, `/api/ai/invoke` и `/api/ai/studio/invoke` → `POST /api/ai/process`, промпты workspace, **admin routing** + список сетей, **AI-студия** в редакторе (`requestType` chat / image / image_edit / video и сценарий «части»), кнопки у текста и медиа поста, перенос готового результата в редактор с локальным сохранением AI-изображения — **[`docs/ai/AI_INTEGRATION.md`](./AI_INTEGRATION.md)**.
   - Далее: при необходимости **batch-черновики** из ответа «несколько постов» (одним действием), варианты текста на канал совместно с `PostVariant` (см. `TZ_BACKLOG.md`).
